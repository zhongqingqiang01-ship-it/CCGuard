# CC 登录器使用说明

当前版本 0.3.1，适用于 Apple Silicon Mac，最低 macOS 14。打开 `dist/CC登录器.app`，从“检查并启动”开始。

## 首次配置

先安装 Shadowrocket、Google Chrome、VS Code 和 Claude Code 扩展。在登录器设置中填写指定出口 IPv4、Shadowrocket 节点全名和工作目录；新安装不预填个人节点或 IP。已有配置、工作目录和 10–60 秒的网页加载上限保持不变。

系统时区必须是 `America/New_York`。可自行在系统设置中切到纽约；也可选填兼容的时区切换 App，其 `Contents/MacOS/EnvironmentSwitch --service-action newYork` 接口应返回 `{"ok":true}`。没有该工具时留空，登录器只核验真实系统时区，不自动索取管理员权限。

首次在“系统设置 → 隐私与安全性 → 辅助功能”允许 CC登录器，用于核验和操作 Shadowrocket、确认 Claude Code 的实际对话页面。本地签名的构建更新后可能需要退出 App、移除旧条目并重新添加当前 App；仅切换旧开关不一定刷新签名。

启动前先保存并退出已有 VS Code。启动器不会输入账号密码，也不会自动发送消息。

## 启动检查

顺序为：指定 Shadowrocket 节点与配置路由 → 纽约时区 → 网站完整检测及网络路径核对 → 打开所选工作目录中的 Claude Code 对话页。

网站评分须严格大于 90；住宅属性、支持地区、风险项、Claude 与 Cloudflare 出口均匹配指定 IP（国内出口允许智能分流，不要求相同）、DNS、WebRTC、时区及两站可达性必须完整通过。全局服务公告、语言不一致、连接较慢仅提示。网页从导航起至少等待 10 秒，单次上限可设 10–60 秒；启动时缺项或出口/时区不一致可等待 10 秒刷新一次，明确风险不重试。

评分、住宅属性、支持地区及风险项仅在每次启动时检测。主窗口中的“启动评分”保留启动结果，不能理解为持续更新的评分。

实际 Claude Code 对话页确认后，自动最小化检测浏览器、Shadowrocket、时区工具和登录器，VS Code 保持前台。独立 Chrome 使用专用配置目录，不读取日常浏览器的标签或登录信息。请保留它运行，以提供后台 DNS/WebRTC 探测上下文。

工作目录决定 Claude Code 历史会话的范围；需要延续历史时选择原项目目录，再在 Claude Code 会话历史中继续对应对话。

## 无刷新后台守护

运行中不会刷新、重新导航检测网页，也不再读取网页里的评分、住宅或风险状态。

- 本地约每 1 秒核验 VPN、节点、配置路由、系统时区、代理配置及守护心跳。
- 约每 30 秒发起后台轻量请求，分别采集国内、Cloudflare、Claude 出口（国内出口可与另外两处不同），核验 claude.ai、anthropic.com 连通性，使用传给 Claude Code 的代理环境。
- DNS/WebRTC 在专用 Chrome 的隔离上下文中重新主动探测；不读取旧 DOM、不依赖页面文字渲染、不刷新整页。DNS 使用独立随机域名和本轮结果接口，WebRTC 重新建立并关闭 ICE 探测连接。
- 全局服务公告通过后台数据请求更新，只提示，不作为强退门槛。

确认 Claude/Cloudflare 出口不符、DNS/WebRTC 泄露、节点/路由/时区或代理配置变化时，关闭所有 VS Code 窗口及关联子进程。后台网络探测超时、临时不可达或结果不完整则提示重试，每次失败后等待 10 秒；从首次未确认起连续 120 秒没有完整恢复才强退。部分结果、重试以及服务公告恢复都不能重置期限，完整关键探测通过才清除重试状态。停滞不返回的探测另有最长失联保护。

辅助功能失效、VPN 断开、明确的网络接口变化、电脑唤醒或独立守护失效仍撤销运行许可。异常后不会自动重启 VS Code。直接手动打开 VS Code 不触发登录器。

WebRTC 按与启动网站一致的限时观察口径判断：成功启动的新 ICE 观察窗口内未暴露公共地址可通过（可能已禁用或阻断），不代表 STUN 一定连通；脚本、连接或初始化错误仍进入重试。DNS 无可观察出口仅代表该轮探测没有观察到解析出口，不是对所有应用 DNS 流量的证明；后台 HTTP 探测也不等于逐条抓包验证实际 Claude 请求。网站内部 DNS/归属地接口和 STUN 服务可能发生变化，无法确认时进入重试，不会补成通过。

## 浮窗和报错历史

浮窗为 70% 透明的圆形磨砂玻璃，白字、直径 128 点，只显示检测/守护状态和最近读到的出口 IP。读到 IP 不代表整轮已通过；超时期间显示“探测重试中”。拖动移动、双击显示主窗口，右键查看历史或隐藏；菜单栏也能恢复。

主窗口、菜单栏及浮窗右键可打开“报错历史”，支持错误/提示筛选、搜索、刷新和原始日志定位。历史与当前状态分开，旧记录不会被改写成当前结果。

关闭主窗口或隐藏浮窗不会结束守护。“结束使用”或“退出登录器”先结束受管 VS Code，再解除守护；未保存内容可能丢失。结束后保留当前时区和 Shadowrocket 状态。

配置保存在 `~/Library/Application Support/CCGuardOpenSource/settings.json`，日志在该目录的 `Sessions/`，不记录对话正文、账号凭据或代理口令。

## 构建与验证

```sh
zsh scripts/build.sh
CLANG_MODULE_CACHE_PATH="$PWD/.build/ModuleCache" \
SWIFTPM_MODULECACHE_OVERRIDE="$PWD/.build/ModuleCache" swift test --disable-sandbox
node scripts/verify-extractor.mjs
node scripts/verify-background-probe.mjs
python3 scripts/verify-watchdog.py
```

守护测试使用独立的 `CCGuardFixture.app` 测试进程，不操作真实 VS Code。`--check-background` 诊断会首次载入专用检测页一次，再执行两轮后台探测并比较页面导航时间；不会启动或关闭 VS Code，输出中的通过与失败须按当轮实际结果理解。
